# Code of Conduct

## Our pledge

We want BriefForge to be a welcoming, respectful, and constructive project for everyone. Contributors, maintainers, reviewers, and users are expected to participate in good faith and to help keep technical discussions focused on the work without demeaning people.

## Expected behavior

- Be respectful and patient with different backgrounds, experience levels, and viewpoints.
- Give and receive actionable feedback about code, design, documentation, and product decisions.
- Use inclusive language and respect names, pronouns, privacy, and boundaries.
- Focus criticism on the work and its impact, not on a person's character.
- Accept that maintainers may make decisions about scope, safety, and project direction.
- Report harassment, threats, discrimination, or security concerns privately when appropriate.

## Unacceptable behavior

- Harassment, discrimination, intimidation, threats, or personal attacks.
- Sexualized language or attention that is unwelcome in a professional project space.
- Publishing private information without permission.
- Deliberate disruption, trolling, or repeated bad-faith participation.
- Sharing credentials, private data, or malicious content through project channels.

## Enforcement

Project maintainers are responsible for clarifying and enforcing this code. They may remove comments, edit or close discussions, reject contributions, restrict participation, or take other action when behavior violates these standards.

Report concerns privately to the maintainers through the repository hosting service. Security vulnerabilities must follow [SECURITY.md](SECURITY.md), not a public issue.

This code applies in repository discussions, issues, pull requests, reviews, chat, and other spaces used for BriefForge work.
